### `main.go`

```go
package main

import (
	"fmt"
	"net/http"
	"time"

	spinhttp "github.com/spinframework/spin-go-sdk/v2/http"
)

func init() {
	spinhttp.Handle(func(w http.ResponseWriter, r *http.Request) {
		if r.Method != http.MethodGet {
			w.WriteHeader(http.StatusMethodNotAllowed)
			return
		}

		moscow := time.Now().UTC().Add(3 * time.Hour)

		iso := moscow.Format("2006-01-02T15:04:05") + "+03:00"
		hourMinute := moscow.Format("15:04")

		w.Header().Set("Content-Type", "application/json")

		fmt.Fprintf(
			w,
			`{"unix":%d,"iso":%q,"hour_minute":%q,"timezone":"UTC+3"}`,
			moscow.Unix(),
			iso,
			hourMinute,
		)
	})
}
```

The handler is registered using the Spin Go SDK's `spinhttp.Handle(...)`.

Moscow time is calculated as UTC+3:

```go
time.Now().UTC().Add(3 * time.Hour)
```

This avoids depending on timezone database files inside the TinyGo WASI environment.

## Task 1 Design Questions

### a) Browser WASM vs server WASM

A browser-targeted Go WebAssembly build such as a `js/wasm` target expects a JavaScript/browser host environment.

That environment provides JavaScript integration and browser APIs, but those APIs do not exist in a server-side WASI runtime.

The server-side build used in this lab targets:

```text
wasip1
```

It does not provide browser objects such as the DOM or `window`. Instead, the component runs against WASI interfaces supplied by a server runtime such as Spin.

The advantage is a portable server-side module with a much narrower host interface and a capability-oriented execution environment.

### b) Why is `-buildmode=c-shared` required?

The Spin Go HTTP component must export the interface expected by the Spin host.

The current Spin template therefore generates:

```text
tinygo build -target=wasip1 -buildmode=c-shared ...
```

Using `-buildmode=c-shared` produces the exports needed for the Spin Go SDK HTTP handler integration.

Without that build mode, the resulting module does not expose the handler in the form expected by Spin, so the host cannot invoke the registered `spinhttp.Handle(...)` handler correctly.

### c) Why use `allowed_outbound_hosts = []`?

Spin follows a capability-based security model.

A component receives only capabilities explicitly granted to it. With:

```toml
allowed_outbound_hosts = []
```

the Moscow-time component is not permitted to make outbound network requests.

The `/time` endpoint does not require external network access, so this follows the principle of least privilege.

This is conceptually similar to:

```text
docker run --network none
```

but the security model is different. Docker isolates networking primarily through Linux namespaces and container networking, while a WASM host controls which capabilities are exposed to the component in the first place.

### d) TinyGo standard-library gaps encountered

The relevant limitation in this lab was timezone-data availability.

A normal Go program might use:

```go
time.LoadLocation("Europe/Moscow")
```

but a TinyGo WASI build cannot rely on embedded operating-system timezone data being available.

For this reason the endpoint calculates Moscow time directly as UTC+3:

```go
time.Now().UTC().Add(3 * time.Hour)
```

Another known TinyGo limitation for this type of application is reflection-heavy JSON serialization such as `encoding/json` with `map[string]any`.

To keep the component simple and robust under TinyGo, the JSON response was generated explicitly using `fmt.Fprintf`.
